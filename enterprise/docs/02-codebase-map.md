## `revision/`: unit apps and shared engines

```
revision/
  shared/                       unit-ui.js/.css (every unit), unit-edu.js (lazy), unit-feedback.js (lazy), paper-gate.js
  a-level/
    shared/                     aqa-papers.js/.css — AQA papers engine (7132, 7138)
    shared-alevel/              biz-* engines generated by make_shared.py (Psychology, Edexcel)
    business-2023/              AQA 7132 (legacy app + Papers tab), includes paper-1/ sub-app
    business-2026/              AQA 7138 (generated)
    psychology/                 AQA 7182 (generated by alevel-build)
    business-edexcel/           Pearson Edexcel 9BS0 (generated by alevel-build)
  btec/
    level-2/it/unit-2/          legacy JSON-data app (data/*.json)
    level-3/
      business/shared/          the ORIGINAL biz-* engines + calculator
      business/unit-{2,3,6,7}/
      sport/unit-{1,2}/
      IT-AAQ/unit-{1..4}/, booklets/   IT (legacy layout: aim_*.html, mindmaps/, predicted-papers/, slides/)
      shared-aaq/               COPY of the business engines + aaq-assignment.* (AAQ subjects only)
      <subject>-aaq/unit-N/     31 AAQ units (computing, construction, early-childhood-development,
                                engineering, health-and-social-care, medical-science)
```

**There are three copies of the `biz-*` engines** (`business/shared`, `shared-aaq`, `shared-alevel`). This is deliberate: a change for one family cannot break another. The cost is that a bug fix must be applied in up to three places. See roadmap item M-6.

### Anatomy of a generated unit app (AAQ / A-Level / Business)

```
unit-N/
  index.html          generated shell (loads unit-ui, engines, then js/*)
  css/style.css       generated, branded
  js/cfg.js           generated: unit meta, colours; A-Level adds AIM_WORD / AIM_LABEL
  js/spec.js          generated from the parsed specification — never hand-edit
  js/papers-data.js   generated: real exam-board papers (transformed data)
  js/data-loader.js   generated
  js/app.js           generated view controller
  js/bank.js          HAND-WRITTEN (AAQ) / ASSEMBLED from content parts (A-Level): K(...) knowledge checks
  js/quiz.js          hand-written: M(...) / TF(...)
  js/cards.js         hand-written: F(...) + B.publish()
  js/guide.js         hand-written: BIZ_GUIDE_DATA
  js/papers-ra10.js   hand-written: six RA10 practice papers (exam units)
  js/assignment-data.js  generated (assignment units)
  js/assignment-help.js  hand-written (assignment units)
```

For A-Level subjects built by `alevel-build`, `js/bank.js`, `guide.js` and `papers-ra10.js` are **assembled** from `training-data/a-level/alevel-build/content/<slug>/{bank,guide,papers-ra10}/NN_*.js`. Edit the parts, never `js/`.

## Naming and versioning conventions

- Unit route keys: `/revision/<board>/<level>/<subject>/unit-N` (BTEC) and `/revision/a-level/<slug>`. AAQ subject slugs end in `-aaq`. IT keeps the legacy `IT-AAQ` folder.
- Cache tokens:

  | Token | Where it lives |
  |---|---|
  | `?v=YYYYMMDD[n]` | On every script and stylesheet tag |
  | `V` (shared AAQ assets) | `build_apps.py` |
  | `V` (shared A-Level assets) | `build_alevel.py` |
  | `V` (refresh assets) | `ra10-refresh.js` |
  | Sub-module versions | `unit-edu.js` and `unit-feedback.js` are versioned inside `unit-ui.js` |

  Bump them together with the change (see PL-13).
- localStorage keys are prefixed `ra10` (for example `ra10-guide-revised-<code>`, `ra10_pylab_v1`, `ra10-site-announcement-dismiss-v1`).
- `session_type` values are unique per unit so that progress stays separate.
